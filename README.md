# Video tools

Three small tools that turn text and footage into finished videos. They make
videos from **your** footage/script - they do not invent footage.

| Tool | What it does |
|---|---|
| `shorts_maker.py` | Gameplay recording -> vertical Shorts (finds your loudest moments, 9:16, hook title, captions, loudness) |
| `story_maker.py` | Text script -> "documentary" video: pictures with callouts, animated charts, counters, effects, sound effects, music |
| `vfx/` | A real fire + smoke simulation (Blender): a missile hits, big explosion, cinematic grade and sound |

## Set up (Windows)

1. Install **Python** from python.org (tick "Add to PATH").
2. Install **ffmpeg**: open a terminal and run `winget install ffmpeg`, then restart the terminal.
3. Check: `python --version` and `ffmpeg -version` both print something.

Only for auto-captions: `pip install faster-whisper`. Only for auto-voiceover: `pip install edge-tts`.

## shorts_maker.py

```
python shorts_maker.py gameplay.mp4 --count 5 --duration 25 --title "WAIT FOR IT"
```
It picks the *loudest* moments, not the *best* - always watch before posting. Use your own gameplay.

## story_maker.py

Write scenes in a text file (see `examples/deep_ocean.txt`), then:
```
python story_maker.py examples/deep_ocean.txt
python story_maker.py my_story.txt --size wide        # normal YouTube instead of vertical
```
Scene commands: `@image`, `@search`, `@caption`, `@circle`, `@bars`, `@counter`, `@fx`, `@sfx`, `@time`,
`@audio`, `@layout`. Run `python story_maker.py -h` for the full list.

* `@search some topic` fetches a picture from Wikimedia Commons (public domain / CC0 / CC BY only) and
  writes `<script>_credits.txt` - paste it in your video description (CC BY requires credit).
* The sound effects and the music bed are generated by the script, so there is nothing to download.
* Check every fact in your script. Only use pictures/music you're allowed to.

## vfx/ - the explosion

Needs [Blender](https://www.blender.org/download/) (free, official build, 4.x or 5.x). Three steps:

```
blender -b -P vfx/explosion_blender.py -- --out boom --res 112 --width 1152 --height 648
python vfx/explosion_post.py boom -o explosion.mp4              # widescreen
python vfx/explosion_post.py boom --vertical -o explosion_short.mp4
```
* The first command simulates the fire/smoke (a few minutes), then renders every frame.
  Rendering fire is slow on a CPU (tens of seconds per frame). With an NVIDIA/AMD GPU add `--gpu`.
* `--stage sim` / `--stage render` run the two halves separately, so you can re-render without re-simulating.
* Lower `--res` / size / `--samples` for quick previews. `python vfx/explosion_blender.py -h` for all options.
* `explosion_post.py` adds bloom, light streaks, colour grade, camera shake, flash, widescreen bars and the
  sound (the boom arrives *after* the flash, like in real life).
* Linux/Ubuntu note: Ubuntu's packaged Blender 4.0 crashes in the fluid solver; see `vfx/ubuntu_blender_fix.c`.

Honest limits: this is a proper physically simulated explosion, but it is a hobby pipeline - the city is
simple procedural blocks and the look is "good CG", not a AAA studio shot. More resolution, a GPU, and
real 3D assets are what close that gap.
